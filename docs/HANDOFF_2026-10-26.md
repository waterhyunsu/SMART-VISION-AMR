# 2026-10-26 주행 개발 인수인계

이 문서는 2026-10-26 작업 종료 상태와 다음 워크스테이션에서 재개하는 방법을 설명합니다.
코드와 문서는 같은 커밋으로 관리합니다. 배터리 충전으로 실물 시험을 중단했으며,
아래의 실물 시험 결과와 코드 검사 결과는 구분해서 읽어야 합니다.

## 1. 종료 시 상태와 다음 할 일

- PC의 Nav2·AMCL·A*·기억 노드·RViz, Pi bringup, 별도 주행 감시 프로세스와 SSH 연결을 종료했습니다.
- 짧은 거리, 중거리, 약 2m 주행과 최종 방향 정렬은 세션 중 사용자 확인으로 성공한 적이 있습니다.
- 3~4m 반복 주행, 벽 근처 우회, 장애물 기억의 장기 효과는 검증 완료 상태가 아닙니다.
- 마지막 목표 위치 허용 오차 15cm 변경은 빌드와 실행 파라미터 확인까지 했습니다.
  변경 후 실물 완주 확인은 전원/통신 문제로 중단됐습니다.
- 인수인계 정리 중 발견한 취소·액션 거절·경로 교체 상태 오류는 추가 보완하고 오프라인 회귀 검사를 했습니다.
  이 보완 이후 로봇을 다시 움직이지 않았습니다.

**재개 순서: 충전 완료 → Pi bringup → 배터리·모터 통신·odom 확인 → PC launch → 초기 위치 → 짧은 목표 → 장애물/장거리 시험.**

## 2. 실제 시스템 구성

```text
Raspberry Pi / TurtleBot3
  OpenCR·바퀴 → turtlebot3_node + diff_drive_controller → /odom, /imu, /battery_state
  LDS-03 → /scan
  robot_state_publisher → 로봇 내부 TF

PC
  map_server + AMCL → /map, map→odom
  /scan + /map + TF → change_memory → observed_obstacles / remembered_cells
  RViz 2D Goal Pose → /smart_vision_amr/goal
      → astar_planner → /smart_vision_amr/path (map)
      → path_follower (odom으로 변환) → Nav2 /follow_path
      → controller_server /cmd_vel_nav
      → velocity_smoother /cmd_vel → Pi turtlebot3_node
```

- **AMCL은 포함되어 있습니다.** 자체 Python 구현은 없지만 `hardware.launch.py`가 Nav2 localization을 실행합니다.
- TF는 `map → odom → base_footprint → base_link`와 센서 프레임이 연결되어야 합니다.
- ArUco·카메라·Gazebo 기능은 현재 저장소에 없습니다. 지금 초기 위치는 RViz의 **2D Pose Estimate**로 지정합니다.
- Nav2의 planner/BT/behavior 서버도 bringup으로 실행되지만, 이 프로젝트 목표는 자체 A*에서 **FollowPath로 직접 전달**합니다.
  Nav2의 NavigateToPose 복구 트리를 자동으로 거친다고 가정하면 안 됩니다.

## 3. 코드 수정과 의도

관련 파일은 `ros2_ws/src/smart_vision_amr/` 아래에 있습니다.

| 파일/부분 | 현재 동작과 변경 이유 |
|---|---|
| `astar.py`, `map_utils.py` | A* 격자 경로 탐색. 8방향 이웃을 탐색하고 대각선 모서리 통과를 검사합니다. 알 수 없는 지도 셀도 막습니다. 장애물 팽창은 원형입니다. |
| `smart_vision_amr/astar_planner.py` | 지도·현재 관측·기억 장애물을 합칩니다. 정적/동적 팽창 영역이 겹친 출발점에서 제한된 탈출을 허용합니다. 실제 점유/미확인 셀과 실제 관측·기억 셀은 통과시키지 않습니다. |
| 같은 파일: 목표 유지 | `FAILED`, TF 대기, 경로 없음 상태에서 목표를 유지하고 1초 주기로 재계획합니다. `SUCCEEDED` 또는 명시적 `CANCELED`이면 목표를 지웁니다. |
| 같은 파일: 경로 없음 | 목표 자체가 막혔는지, 팽창 영역인지 로그에 표시합니다. 경로 없음으로 전환할 때 빈 Path를 발행해 실행 중 경로를 중단합니다. |
| 같은 파일: 목표 보정 | 원래 목표에 경로를 못 찾으면 주변의 도달 가능한 셀을 찾습니다. hardware 설정은 요청 좌표에서 **5cm 이내**로 제한합니다. |
| `smart_vision_amr/path_geometry.py` | 현재 경로의 남은 구간과 새 경로를 비교합니다. 전진 때문에 경로 시작점만 달라진 것은 유지합니다. 경로 동등성 허용 오차를 **5cm → 12cm**로 조정해 작은 흔들림에 의한 반복 취소를 줄였습니다. |
| `smart_vision_amr/path_follower.py` | 같은 목적지의 경로 변경은 **0.6초 대기** 후 교체합니다. 다른 목적지로 판정하면 즉시 교체합니다. 끝점 거리 25cm·방향 차이 0.15rad는 이 목적지 비교 기준이며 도착 판정 기준과 다릅니다. |
| 같은 파일: 실패/취소 | 실패·액션 거절 뒤 동일 경로를 다시 보낼 수 있게 중복 차단 상태를 해제합니다. 경로 없음/안전 감시/경로 교체에 따른 내부 취소와 사용자 취소를 구분합니다. |
| 같은 파일: 명시적 취소 | 활성 액션이 없어도 대기 경로를 비우고 `CANCELED`를 알려 A*가 보관한 목표를 지웁니다. 승인 대기 중 액션은 승인 뒤 취소하며, 늦게 도착한 종료 결과가 취소 상태를 덮지 않게 처리합니다. |
| 같은 파일: TF/감시 | map 경로를 전송 시 odom으로 변환합니다. 오래된 센서·TF·코스트맵이나 로봇 위치 불일치를 확인하면 경로를 거부/취소합니다. |
| `launch/hardware.launch.py` | Nav2를 개별 프로세스로 실행합니다. TF2 우회 라이브러리, AMCL TF 허용 시간 0.1초, 속도·반경·진척 판정·도착 조건을 적용합니다. |
| 같은 파일: 도착 방향 | DWB 최종 회전 시작 거리와 Nav2 위치 도착 허용 오차를 동일하게 맞췄습니다. 세션 중 25cm 설정을 거쳐 최종 저장 값은 **둘 다 15cm**입니다. 원래 외부 YAML 값은 각각 5cm/25cm로 달랐습니다. |
| `change_memory.py`, `obstacle_memory.py` | 현재 장애물 관측과 지속 기억을 분리합니다. 기억은 별도 JSON과 장애물 셀 집합으로 유지하며 원본 지도 PGM을 수정하지 않습니다. |
| `scripts/install_tf2_02520_overlay.py` | 특정 Humble TF2 버전에서 관측한 문제를 우회하기 위한 사용자 디렉터리 설치 도구입니다. 공식 ROS 스냅샷 서명과 패키지 해시를 검사합니다. |

목표가 유지되어도 로봇이 통과할 수 있는 경로가 없거나 센서가 끊기면 정지합니다.
8방향 A* 탐색은 로봇이 전후좌우로 직접 움직일 수 있다는 뜻이 아닙니다.
현재 설정에는 자동 후진 탈출이나 모든 상황에서 목적지 도착을 보장하는 복구 기능이 없습니다.

## 4. 최종 저장된 주요 설정

실행 중 임시로 바꾼 파라미터보다 아래 소스 설정이 우선입니다. 재시작하면 이 값으로 돌아옵니다.

| 항목 | 값 |
|---|---|
| 로봇 / 라이다 / ROS domain | Waffle Pi / LDS-03 / 16 |
| 기본 지도 | `maps/classroom_map.yaml` + `.pgm`, 5cm/셀 |
| A* 장애물 팽창 | 5셀 = 25cm |
| Nav2 로봇 반경 / inflation radius | 20cm / 25cm |
| DWB 전진 최대 / 회전 최대 | **0.16m/s / 0.5rad/s** |
| velocity smoother / motion mux 상한 | `[0.16, 0.0, 0.5]` — DWB와 같은 상한 |
| Nav2 위치 도착 / DWB 회전 시작 | **0.15m / 0.15m** |
| 방향 도착 허용 오차 | 현재 외부 TurtleBot3 YAML: 0.25rad, 약 14.3도 |
| A* 대체 목표 허용 거리 | 0.05m |
| 진척 판정 | 20초 동안 0.1m 이동하지 못하면 실패 가능 |
| 경로 동등성 / 변경 대기 | 0.12m / 0.6초 |
| scan·odom·footprint 최대 나이 | 0.75초 |
| local costmap 최대 나이 | 1.5초 |
| 기억 기본값 | `memory_enabled:=true` — 명령에 매번 붙일 필요 없음 |

20cm 반경에 25cm inflation을 썼다는 것이 **로봇 외곽에서 25cm를 더 띄운다**는 뜻은 아닙니다.
반경의 기준 프레임, 라이다 설치 위치, 지도 격자 오차가 있으므로 실제 여유 공간은 실물로 확인해야 합니다.
15cm 도착 판정 역시 odom 기준 컨트롤러 목표에 적용됩니다. 지도 셀 중앙 오차·대체 목표·AMCL 보정까지 포함한
실제 map 좌표 오차가 반드시 15cm 이하라고 보장할 수는 없습니다.

## 5. 기억 기능: “5회 이상 AND 최소 2초”

**5번 주행한다는 뜻이 아닙니다. 같은 지도 셀을 장애물로 관측한 횟수입니다.**

1. 라이다 한 스캔의 반사점을 지도 좌표의 셀로 바꿉니다. 한 스캔에서 여러 광선이 같은 셀을 맞혀도 한 번입니다.
2. 같은 셀의 인정 관측은 최소 0.25초 간격으로 셉니다.
3. 인정 관측이 **5회 이상이고**, 최초~마지막 인정 관측 사이가 **2초 이상**이어야 기억으로 확정합니다.
4. 5회 관측을 1초 안에 마쳐도 아직 확정하지 않습니다. 이후 2초 조건까지 충족하는 관측이 필요합니다.
5. 반대로 그 셀이 비었다고 5회 이상·최소 2초간 관측되면 기억에서 해제합니다.

물체의 이름이나 ID를 추적하지 않습니다. 같은 소화기라도 반사점이 여러 셀에 걸치면 여러 셀을 기억합니다.
일시적으로 보이지 않는 기간만으로 관측 누적이 초기화되지는 않으므로 “연속으로 끊김 없이 2초” 조건은 아닙니다.
해당 셀이 실제로 비었다는 관측이 들어오면 점유 누적을 초기화합니다.
기본 지도에서 이미 벽이거나 미확인인 셀은 새 장애물 기억 대상에서 제외합니다.

- 현재 스캔 장애물은 확정 전에도 즉시 A*에 반영합니다.
- 확정 기억은 `~/.ros/smart_vision_amr/classroom_memory.json`에 저장합니다.
- `memory_enabled:=false`는 지속 기억을 끄며, 현재 라이다 장애물 회피는 유지합니다.
- 기억 초기화 뒤 소화기가 그대로 보이면 다시 5회·2초 조건을 채워 기억되는 것이 정상입니다.
- `/remembered_cells` 숫자는 셀 인덱스 `y * 지도너비 + x`입니다. 물체 개수나 주행 횟수가 아닙니다.
- 저장 기억을 불러올 때 지도 내용·메타데이터 서명을 확인합니다. 저장 파일 안의 관측 기준도 복원됩니다.

## 6. TF 문제와 마지막 하드웨어 오류

초기에는 중복 `/map` 발행자와 `/follow_path` 서버가 있었고, 이후 중복을 정리했습니다.
`map` TF를 못 찾으면서 곧바로 도착이라고 보고하는 현상도 관측했습니다.
개별 Nav2 프로세스 실행, odom 경로 변환, 입력 감시, TF2 0.25.20 사용자 라이브러리 적용으로 대응했습니다.
이 PC의 시스템 TF2는 0.25.23입니다. 다른 장비의 모든 TF 오류를 같은 버전 문제로 단정하면 안 됩니다.

마지막 시험에서 확인한 사실:

- `/odom` 발행자가 사라져 경로 추종기가 `odom is stale`로 실행을 거부했습니다.
- Pi bringup 재시작 직후에는 `/odom` 약 20Hz와 배터리 메시지가 복구됐습니다.
- 최신 수신 배터리는 **11.01V / 표시 28.33%**, `/sensor_state`는 **`torque: false`**였습니다.
- 이후 `DynamixelSDKWrapper: There is no status packet!`가 반복됐습니다.
- 마지막에는 **`*** stack smashing detected ***`**, `turtlebot3_ros` **exit code -6**으로 노드가 종료됐습니다.
- 라이다 노드가 살아 있어도 배터리·바퀴/오도메트리 노드는 죽을 수 있습니다.

배터리/전원 불안정이 의심되어 충전을 위해 중단했습니다. 다만 **배터리만이 원인이라고 확정하지 않았습니다.**
11.1V는 배터리의 공칭 전압이며, 그 값 자체가 차단 기준은 아닙니다.
`There is no status packet`는 Pi의 드라이버가 OpenCR 통신 응답을 받지 못한 증거이고,
메모리 손상 검사로 프로세스가 종료된 원인도 별도 확인이 필요합니다.
완충 후에도 반복되면 USB/전원 연결, OpenCR, 드라이버/펌웨어를 조사해야 합니다.
`power_supply_status: 0`은 충전 상태 미상이며 충전 중이라는 뜻이 아닙니다.

## 7. 다른 워크스테이션 준비

대상은 **Ubuntu 22.04, ROS 2 Humble, x86_64/amd64 PC**입니다. ROS apt 저장소 설정이 완료되어 있어야 합니다.
TF2 설치 스크립트는 amd64용 패키지만 받으므로 ARM PC에 그대로 사용하지 마세요.
로봇 IP는 마지막 확인 기준 `192.168.0.187`, 계정은 `robot`입니다. DHCP로 바뀔 수 있습니다.
비밀번호와 GitHub 토큰은 저장소에 기록하지 않습니다.

```bash
sudo apt update
sudo apt install git gnupg python3-colcon-common-extensions python3-rosdep \
  ros-humble-desktop ros-humble-navigation2 ros-humble-nav2-bringup \
  ros-humble-turtlebot3-navigation2 ros-humble-turtlebot3-msgs

cd ~
git clone https://github.com/waterhyunsu/SMART-VISION-AMR.git
cd ~/SMART-VISION-AMR
git log -1 --oneline
source /opt/ros/humble/setup.bash
# rosdep 최초 설치 PC에서만 실행. 이미 초기화됐다면 생략.
sudo rosdep init
rosdep update
cd ros2_ws
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install --packages-select smart_vision_amr
source install/setup.bash
```

기존 clone이 있다면 작업 파일을 확인한 후 `git pull --ff-only origin main`을 사용합니다.
다른 PC의 `build/`, `install/`, `log/`를 복사하지 말고 새 PC에서 빌드하세요.

TF2 버전 확인:

```bash
python3 -c "import xml.etree.ElementTree as E; print(E.parse('/opt/ros/humble/share/tf2/package.xml').getroot().findtext('version'))"
```

**0.25.21~0.25.24이면** 다음을 한 번 실행해야 현재 launch가 시작됩니다.

```bash
cd ~/SMART-VISION-AMR
python3 scripts/install_tf2_02520_overlay.py
```

설치 위치는 `~/.local/share/smart_vision_amr/tf2-0.25.20/`입니다. clone으로 옮겨지지 않습니다.
서명/해시 검사가 실패하면 우회하지 말고 설치 오류부터 확인하세요.
해당 범위 밖의 버전은 launch가 이 overlay를 강제하지 않지만, 실제 TF 동작 확인은 여전히 필요합니다.

이 PC의 Nav2 controller는 1.1.20, 시스템 TF2는 0.25.23이었습니다.
실제 선택된 TurtleBot3 navigation 패키지는 `~/turtlebot3_ws`의 2.3.7이었으며,
그 `waffle_pi.yaml`은 시스템 apt 2.3.6의 YAML과 동일했습니다.
새 PC에서는 다음으로 선택된 패키지를 확인하세요. 덮어쓰지 않은 Nav2 값은 해당 YAML에 의존합니다.

```bash
ros2 pkg prefix turtlebot3_navigation2
ros2 pkg prefix nav2_controller
```

### 현재 학습한 장애물 기억도 옮기려면

**Git에는 코드와 기본 지도만 들어갑니다. 지금 학습한 기억 JSON은 별도로 옮겨야 합니다.**
새 PC에 파일이 없으면 빈 기억으로 시작해 다시 관측합니다. 기존 기억이 필요할 때만 다음처럼 복사합니다.

```bash
mkdir -p ~/.ros/smart_vision_amr
# OLD_PC_IP를 기존 remote-1 PC의 실제 주소로 바꿉니다. 로봇 Pi 주소가 아닙니다.
scp student@OLD_PC_IP:~/.ros/smart_vision_amr/classroom_memory.json \
  ~/.ros/smart_vision_amr/classroom_memory.json
```

동일 지도·동일 장소에서만 복원하세요. Pi에는 PC의 A* 패키지를 복제할 필요가 없으며,
Pi의 TurtleBot3/라이다 bringup 설치는 계속 사용합니다.

## 8. 재개 시 터미널별 실행 순서

### 터미널 1 — Pi bringup

```bash
ssh robot@192.168.0.187
source /opt/ros/humble/setup.bash
[ -f ~/turtlebot3_ws/install/setup.bash ] && source ~/turtlebot3_ws/install/setup.bash
export TURTLEBOT3_MODEL=waffle_pi LDS_MODEL=LDS-03 ROS_DOMAIN_ID=16 ROS_LOCALHOST_ONLY=0
ros2 launch turtlebot3_bringup robot.launch.py use_sim_time:=false
```

### 터미널 2 — PC에서 하드웨어 확인 후 Nav2 실행

```bash
source /opt/ros/humble/setup.bash
source ~/SMART-VISION-AMR/ros2_ws/install/setup.bash
export TURTLEBOT3_MODEL=waffle_pi ROS_DOMAIN_ID=16 ROS_LOCALHOST_ONLY=0

# 새 Nav2를 켜기 전: 기존 /follow_path 서버와 /map 발행자가 없어야 합니다.
ros2 action info /follow_path
ros2 topic info /map -v

# 아래 두 hz 명령은 각각 몇 초 확인한 뒤 Ctrl+C로 끝냅니다.
ros2 topic hz /scan
ros2 topic hz /odom
ros2 topic echo /battery_state --once
ros2 topic echo /sensor_state --once
```

Pi 통신 오류가 반복되거나 odom/배터리가 사라지면 여기서 원인을 해결합니다.
`torque: false`를 봤다고 모터를 강제로 켜서 우회하지 않습니다.
하드웨어가 안정된 뒤 같은 PC 터미널에서 실행합니다.

```bash
ros2 launch smart_vision_amr hardware.launch.py
```

기억은 기본 활성화입니다. 비교 시험에서만 `memory_enabled:=false`를 붙입니다.
다른 지도는 `map:=/절대경로/map.yaml`, GUI 없이 진단할 때는 `use_rviz:=false`를 붙입니다.
같은 로봇을 대상으로 이전 PC와 새 PC의 Nav2를 동시에 켜지 마세요.

### 터미널 3 — PC 진단

```bash
source /opt/ros/humble/setup.bash
source ~/SMART-VISION-AMR/ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=16 ROS_LOCALHOST_ONLY=0
ros2 action info /follow_path
ros2 topic info /map -v
ros2 lifecycle get /map_server
ros2 lifecycle get /amcl
ros2 lifecycle get /controller_server
ros2 lifecycle get /velocity_smoother
ros2 topic info /local_costmap/published_footprint -v
```

정상 기준은 FollowPath **서버 1개**, map **발행자 1개**, 위 lifecycle 노드 **active [3]**입니다.
액션 클라이언트 수나 `/cmd_vel` 발행자 수는 1개보다 많을 수 있으며 숫자만으로 중복 실행을 판정하지 않습니다.
footprint 구독은 현재 `TRANSIENT_LOCAL`이므로 새 Nav2 발행자의 durability가 `VOLATILE`이면 호환되지 않습니다.
이 경우 `No local costmap footprint received`를 확인하고 QoS를 맞춰야 합니다.

RViz에서 **2D Pose Estimate**로 실제 위치·방향을 지정한 뒤:

```bash
ros2 run tf2_ros tf2_echo map base_footprint
```

연속 출력이 나오고 좌표·방향이 실제 로봇과 맞으며 라이다/지도가 겹치는지 확인합니다.
TF 출력만 있다고 위치 추정 정확도가 보장되는 것은 아닙니다.
Nav2/AMCL 재시작 또는 로봇 odom 리셋 이후에는 초기 위치를 다시 확인·지정합니다.

## 9. 남은 시험과 관측 명령

1. 충전 후 정지 상태에서 odom·배터리·scan이 지속되고 Pi 통신 오류가 재발하지 않는지 확인.
2. 열린 공간 정면 30~50cm 목표: 출발, 경로 추종, 정지, 최종 방향 확인.
3. 중거리 및 복귀: `Failed to make progress`와 경로 반복 교체 여부 확인.
4. 고정 장애물 관측: 기억 확정 후 우회, 장애물 제거 후 기억 해제 확인.
5. 열린 3~4m 경로: 완주와 마지막 위치·방향 오차 기록.
6. 실패/경로 없음 대기 중 명시적 취소: 이후 조건이 회복돼도 목표가 자동 재개되지 않는지 확인.

목표는 RViz **2D Goal Pose**로 지도 안의 도달 가능한 빈 공간에 찍습니다.
지도 밖 목표는 현재 planner의 예외 처리가 충분하지 않으므로 사용하지 않습니다.

```bash
# 이 명령은 상태가 발행될 때 출력합니다. 정지해 있다고 계속 출력되는 것은 아닙니다.
ros2 topic echo /smart_vision_amr/navigation_status
ros2 topic echo /cmd_vel
ros2 topic echo /smart_vision_amr/remembered_cells --once --qos-durability transient_local

# 명시적 취소 — 현재 액션뿐 아니라 대기/재시도 목표도 취소
ros2 service call /smart_vision_amr/cancel_navigation std_srvs/srv/Trigger '{}'
# 기억 저장
ros2 service call /smart_vision_amr/save_memory std_srvs/srv/Trigger '{}'
# 기억 초기화 — 비교 시험이 필요할 때만
ros2 service call /smart_vision_amr/clear_memory std_srvs/srv/Trigger '{}'
```

기본 RViz 화면에는 지도·로봇 위치 축·A* 경로만 표시됩니다.
벽 근처 멈춤을 조사할 때 `/scan`, `/local_costmap/costmap`, `/local_costmap/published_footprint` 표시를 추가하면
계획 경로와 실제 장애물/로봇 외곽의 관계를 확인할 수 있습니다.

현재 0.6초 경로 변경 대기는 새 변경이 들어오면 다시 시작합니다.
관측 흔들림이 계속되면 새 경로 반영이 더 늦어질 수 있으므로, 이 부분은 반복 주행에서 관찰할 항목입니다.
기억 노드의 관측 좌표 변환은 최신 TF를 사용하므로 빠른 회전·시계/TF 오차가 기억 셀에 미치는 영향도 남은 확인 항목입니다.

## 10. 코드 검사 및 종료

로봇을 켜지 않고 실행 가능한 회귀 검사:

```bash
cd ~/SMART-VISION-AMR
source /opt/ros/humble/setup.bash
PYTHONPATH="$PWD/ros2_ws/src/smart_vision_amr:$PYTHONPATH" \
  python3 -m unittest discover -s tests -v
cd ros2_ws
colcon build --symlink-install --packages-select smart_vision_amr
```

테스트는 ROS 메시지/라이브러리를 가져오지만 ROS 노드를 초기화하거나 로봇에 명령을 보내지 않습니다.
오프라인 검사는 상태 전이·경로 계산·기억 조건을 확인하며 실물 충돌 회피/배터리/통신 검증을 대신하지 않습니다.

작업 종료 시 목표 취소 → PC launch 터미널 Ctrl+C → Pi bringup 터미널 Ctrl+C 순서로 종료합니다.
RViz 창만 닫으면 Nav2와 A*는 계속 실행될 수 있습니다. 종료 후 로봇 전원/충전은 현장에서 처리합니다.
